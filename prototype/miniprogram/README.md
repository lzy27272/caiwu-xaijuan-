# 酒店管理公司财务管理平台 · 微信小程序移动端原型

14 家独立法人酒店的单体财务管理平台移动端原型。纯前端 + 本地模拟数据，**不连接任何后端、不发起网络请求**，所有金额与指标均来自 `utils/data.js`。用于方案评审与交互演示，不作为生产代码。

仅一处例外：`wx.setStorageSync('lastAccount')` 用于「记住上次收款账户」，属演示必需的本地缓存，清除小程序缓存即还原。

## 一、导入与运行

1. 打开「微信开发者工具」→ 导入项目。
2. 目录选择：`prototype/miniprogram`（即本 README 所在目录，`app.json` 在这一层）。
3. AppID 选择「测试号」，或直接使用工程内已配置的 `touristappid`（游客模式，无需注册）。
4. 基础库版本 `3.5.0`，`compileType: miniprogram`，ES6 转 ES5 已开启。导入后直接编译即可，无需 `npm install`、无外部依赖。
5. 推荐先看两个入口：
   - 编译模式「工作台」：默认身份为总部财务经理，可切 6 种身份；
   - 编译模式「单据详情（阻断样例）」：`pages/detail/detail?id=BX2026100026`，演示发票查重命中的阻断态。

切换身份的方式：工作台右上角「切换身份 ▾」，或「我的」页身份卡。切换后工作台、待办、单据的数据范围与 KPI 口径同步重算。

## 二、页面结构

```
pages/workbench/   工作台（tabBar 第 1 项）
  深蓝渐变头（#0C447C → #185FA5 → #378ADD）+ 问候语 + 会计期间/上月关账/待办数
  角色 picker（6 身份）→ 整页 setData 重算
  4 个 KPI 2×2，按角色取不同指标（门店侧看本店，总部侧看集团）
  我的待办：待我审批 / 待我付款 / 异常待跟进 / 全部单据，按角色过滤
  快捷入口 4 列宫格（8 项，按角色过滤）
  财务日历：按角色过滤后取最近 6 条，已完成置灰、2 日内到期高亮
  通知与制度：3 条，点击 wx.showModal 展示正文
pages/todo/        待办（tabBar 第 2 项）
  三统计：待我审批张数 / 合计金额 / 其中阻断级张数
  分段 tabs 与工作台同口径；列表含风险标签、当前节点、提交时间；空态文案完整
pages/docs/        单据（tabBar 第 3 项）
  全量 13 张单据，按 全部 / 审批中 / 已审批 / 已驳回 四态筛选，带数量角标
  右下角悬浮「+ 发起」按钮：新建费用报销 / 新建付款申请（showActionSheet 二选一）
pages/newdoc/      新建单据（非 tabBar，navigateTo?type=expense|payment）
  顶部「费用报销 / 付款申请」分段切换
  主体自动锁定（门店端）或可切换（总部端）
  费用项目两级 picker：一级大类 → 二级明细，实时显示归集的预算项
  收款信息：常用账户横滑套用、开户行与账号必填、报销可记住上次账户
  附件三入口：拍照 / 相册 / 聊天文件（原型用样例文件模拟）
  提交前检查：预算不足（红）、疑似拆单（橙）、账户不一致（橙）、缺付款依据（橙）
  提交后 redirectTo 详情页，审批链从「店长审批」开始
pages/invadd/      发票采集（非 tabBar，navigateTo）
  两步式：上传（拍照/相册/手工录入）→ 识别 → 人工确认 → 入库
  列表态：待识别 / 已识别双计数，逐条「识别」或「确认」，可移除
  确认态：原票预览占位 + 票面字段表单（代码/号码/日期/票种/销售方/金额/税额/税率/类目/主体）
  低置信字段黄底标注「低置信」，人工改过即消失
  实时校验三条：查重（票号全局唯一）/ 税额与税率自洽 / 抵扣判定（按类目）
  查重命中直接禁用「确认并入库」，并展示首次入库门店、单据号、开票日
  入口：工作台快捷入口「发票采集」、「我的」菜单
pages/detail/      单据详情（非 tabBar，navigateTo）
  单据头 + 审批链横向滚动（✓ 已完成 / 当前 / 未到 / × 驳回）
  处理轨迹：谁在什么时候提交 / 通过 / 驳回（存量单据按进度反推）
  风险块（block 红底「阻断」、warn 黄底「警告」，含规则 code）
  费用明细表、关联发票、其他附件、银行回单
  底部固定操作栏：有权限显示「驳回 / 审批通过」，否则显示「无审批权限」并说明原因
pages/mine/        我的（tabBar 第 4 项）
  身份卡 + picker、会计期间（2026-10 / 上一期间 2026-09 已关账）、数据范围
  发起费用报销 / 发起付款申请（移动端快捷入口）
  我的单据、收款账户（查看/清除已记住的账户）、发票池、预算执行、主数据、关于本原型
utils/data.js      模拟数据（与 PC 端 prototype/assets/data.js 逐字一致，仅追加 module.exports）
utils/flow.js      getFlow / canApprove，与 PC 端 assets/core.js 同一套审批链
utils/format.js    fmt / fmt0 / wan / pct / relDay / weekday / greeting
```

审批链口径（与 PC 端完全一致）：

```
提交申请 → 店长审批 → 门店财务审核
  ├─ 金额 < 3,000        直接 → 出纳付款
  ├─ 3,000 ≤ 金额 < 20,000   + 总部财务审核
  ├─ 20,000 ≤ 金额 < 50,000  + 总部财务审核 + 财务总监审批
  └─ 金额 ≥ 50,000           + 总部财务审核 + 财务总监审批 + 总经理审批
→ 出纳付款
```

`canApprove(doc, role)`：`role === 'cfo'` 恒为 true，否则要求当前节点 `role` 与身份相同；调用方需自行限定 `doc.status === 'pending'`。

## 三、接后端时要改哪些文件

| 文件                             | 改法                                                                                                                 |                                             |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------- |
| `utils/data.js`                | 整体替换为接口层：`wx.request` 拉 PERIOD / STORES / GROUP / DOCS / INVOICES / BUDGETS / CALENDAR / NOTICES。建议保留同名导出，页面代码零改动。 |                                             |
| `app.js`                       | `globalData.docs` 改为登录后由接口填充；新增 `wx.login` → `code` 换 session，用后端返回的角色列表替换 `roleKeys`。删除 `onLaunch` 的空实现。          |                                             |
| `utils/flow.js`                | 审批链由后端按单据类型 + 金额 + 组织架构下发（`doc.flow` 字段），前端不再自行 `if (amount < 3000)` 分档；`canApprove` 改为读取后端返回的 `doc.canApprove`。   |                                             |
| `pages/detail/detail.js`       | `onApprove` / `onReject` 由本地改状态改为 \`POST /docs/:id/approve                                                         | reject`，带单据指纹做幂等；成功后再 `refresh()\`，失败回滚并提示。 |
| `pages/workbench/workbench.js` | KPI 与待办聚合改为调用 `GET /workbench?role=`；当前是前端 13 条单据全量过滤，后端应分页。                                                       |                                             |
| \`pages/todo                   | docs/*.js\`                                                                                                        | 列表改分页接口，筛选条件下沉到查询参数。                        |
| `pages/mine/mine.js`           | 身份、期间、数据范围改由会话接口返回；「关于本原型」入口删除或改为版本信息。                                                                             |                                             |

保持不变的部分：`app.wxss` 的设计令牌与全部 `.wxss`、`.wxml` 结构、`utils/format.js` 的格式化口径。

## 四、与 PC 端原型的复用关系

- **数据同源**：`utils/data.js` 就是 `prototype/assets/data.js` 原样搬运，仅在文件末尾追加 `module.exports`，字段一个不少。两边算出的 `GROUP.revenueNet = 12,648,382`、`STORES.length = 14`、`DOCS.length = 13` 完全一致，移动端不与 PC 端产生第二套口径。
- **审批链同源**：`utils/flow.js` 与 `assets/core.js` 的 `getFlow` / `canApprove` 逐行对应，仅把提交节点的 `role` 由 `'申请人'` 规范为 `'applicant'`（PC 端该节点不参与角色比较，行为等价）。
- **指标同源**：工作台 KPI 的六套角色口径照搬 `assets/view-workbench.js` 的 `wbKpis()`，分栏规则照搬 `wbTabs()`，日历类型与紧急判定照搬 `WB_CAL_TYPE` / `wbRel()`。
- **不共用**：PC 端的 SVG 图表（折线、条形）、侧边导航、弹窗容器不迁移到移动端——屏幕宽度不足以承载，移动端改用 KPI 卡 + 列表 + 原生 `wx.showModal`。
- **并列关系**：移动端是独立工程，不改 PC 端的页面与样式；两端同期共用同一份模拟数据与同一套审批链口径，PC 端另有「工作台」页（`assets/view-workbench.js`），信息架构与小程序工作台一一对应。

## 五、已知限制

1. **无持久化**：审批动作只改 `app.globalData.docs`（内存中的深拷贝），杀进程或重新编译即还原为初始 13 条。这是刻意设计，避免演示时数据被改乱。
2. **身份是手动切换的**：没有登录与鉴权，picker 可任意切到财务总监，因此「无审批权限」只演示了前端判断，不代表真实权限控制。生产环境必须由后端校验。
3. **数据范围硬编码**：门店员工固定看「陈晓燕」，门店店长 / 门店财务固定看城东店（S01），因为模拟数据里只有这一个门店有完整单据。真实系统按 `storeId` 会话解析。
4. **快捷入口只有部分可用**：发票池、凭证中心、损益表、预算、结账、主数据在移动端未实现页面，点击提示「原型未开放该页面」，仅用于表达信息架构。
5. **图表缺失**：无趋势折线、无预算进度条图形，仅用文字与色块表达，属于移动端取舍。
6. **无发票 OCR、无附件预览、无手写签名、无消息推送**：审批链中的「自动升级提醒」只在文案中出现，没有定时任务。
7. **金额与税额是静态的**：`taxAmount` 直接取自模拟数据，未按明细行 `taxRate` 重算；`utils/data.js` 中的 `seeded()` 伪随机保证每次生成一致，但换 `PERIOD.days` 后所有门店指标会整体变化。
8. **未做无障碍与深色模式**：字号固定 34/26/22rpx，未接 `prefers-color-scheme`。
